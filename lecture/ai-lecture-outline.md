## 문체 규칙 (전 슬라이드 공통)

- 명사체 · 개조식 고정 — `~합니다 / ~입니다 / ~해요` 등 서술형 어미 금지
- 예: ~~"코딩은 배우지 않습니다"~~ → **"코딩 학습 아님 / 내 업무 적용만"**
- 예: ~~"AI가 잘하는 일을 알아봅시다"~~ → **"AI 강점 vs 한계"**
- 부호 위주 표기 — `·` `→` `vs` `/`, 문장 끝 마침표 생략
- 스피커 노트도 메모형 개조식 (문장 나열 금지)

## S04 · 두 현장을 겪은 시선 ⏱ 1분

**핵심 메시지** — 제조 + IT → 오늘 강의의 앵글

- 제조 현장: 반복·표준화된 절차가 많음
- IT 현장: 그 절차를 자동화로 옮기는 방법을 다룸
- 결론: **자동화 대상 발굴은 현업이 유리 / 구현은 도구가 대신**

> **스피커 노트**
> - 이 장이 2장 전체의 전제 — "여러분이 후보를 아는 사람"

# 2. 업무/일과의 변화 (14분)

## S05 · 통계로 보는 변화 ① 개발자 ⏱ 2분

**핵심 메시지** — 사용은 보편화 / 신뢰는 하락

| 지표 | 수치 | 비고 |
|---|---|---|
| AI 도구 사용 또는 사용 예정 | **84%** | 2024년 76% → 상승 |
| 전문 개발자 중 매일 사용 | **51%** | — |
| 정확성 불신 | **46%** | 신뢰 33%보다 높음 |
| "AI 코드 디버깅에 시간 소요" 불만 | **45%** | — |

- 출처: Stack Overflow Developer Survey 2025 (https://survey.stackoverflow.co/2025/ai)

> **스피커 노트**
> - 포인트 = "많이 쓴다"가 아니라 "쓰면서도 검증한다"
> - 뒤의 가드레일(S19) 복선으로 사용

## S06 · 통계로 보는 변화 ② 기업·직장인 ⏱ 2분

**핵심 메시지** — 도입은 대세 / 격차는 직급·조직

| 지표 | 수치 | 출처 |
|---|---|---|
| 1개 이상 업무 기능에서 AI 상시 사용 조직 | **88%** | McKinsey State of AI 2025 |
| 화이트칼라 중 일상 업무 빈번 사용 | **27%** (전년 대비 +12%p) | 〃 |
| 관리자·임원 33% vs 실무자 **16%** | 2배 격차 | 〃 |
| 국내 근로자 업무 목적 AI 사용 경험 | **51.8%** (정기 활용 17.1%) | 한국은행, 2025.8 |
| 국내 기업 생성형 AI 도입률 | **61%** / 조직 내재화 **6.7%** | 삼성SDS 실태조사 |

> **스피커 노트**
> - 강조 지점 = 도입률과 내재화율의 간극
> - "회사가 도입" ≠ "내가 활용" → 오늘 목표는 후자

## S07 · 빅테크 개발자 일과 (Before) ⏱ 1.5분

**핵심 메시지** — 시간 대부분 = 직접 작성

| 시간 | 활동 |
|---|---|
| 오전 | 요구사항 확인 · 자료 검색 |
| 오후 | 직접 코드 작성 (비중 최대) |
| 저녁 | 오류 수정 · 문서 정리 |

> **스피커 노트**
> - 비개발자용 치환: 코드 = 문서/보고서

---

## S08 · 빅테크 개발자 일과 (After) ⏱ 1.5분

**핵심 메시지** — 작성 ↓ / **판단·검토** ↑

| 시간 | 활동 | 변화 |
|---|---|---|
| 오전 | 작업 정의 · AI에 위임 | 지시 설계 비중 ↑ |
| 오후 | 결과 검토 · 수정 요청 반복 | 검증 비중 ↑ |
| 저녁 | 최종 책임 확인 · 배포 | 판단 비중 ↑ |

- 핵심: 산출물 생산자 → **산출물 감독자**

> **스피커 노트**
> - S05의 "디버깅 불만 45%"와 연결 — 검토 비중이 늘어난 증거

---

## S09 · 개발자만의 변화인가 ⏱ 1분

**핵심 메시지** — 동일 구조가 모든 문서 업무로 이동

- 공통 구조: `초안 생성 위임 → 사람 검토 → 확정`
- 적용 대상: 보고서 · 메일 · 회의록 · 견적 · 규정 검색 · 데이터 정리
- 전환 문장: **"코드가 문서로 바뀌었을 뿐"**

> **스피커 노트**
> - 여기서 청중 시선 전환 — 남의 얘기 → 내 얘기

## S10 · 사내 비개발 직무의 변화 ⏱ 2.5분

**핵심 메시지** — 직무별 진입 지점 상이

| 직무 | 반복 업무 | AI 적용 지점 | 사람의 몫 |
|---|---|---|---|
| 기획 | 자료 조사 · 보고서 초안 | 초안 · 요약 · 구조화 | 논리 검증 · 의사결정 |
| 영업 | 견적 · 고객 메일 · 방문기록 | 문안 생성 · 이력 요약 | 가격 · 관계 판단 |
| 구매 | 사양 비교 · 발주 문서 | 표 정리 · 비교표 생성 | 조건 협상 |
| 품질 | 불량 리포트 · 원인 정리 | 데이터 요약 · 유사사례 검색 | 원인 확정 · 조치 |
| 관리 | 규정 조회 · 양식 작성 | 규정 검색 · 양식 채움 | 규정 해석 · 승인 |

- ★[자사 실제 사례로 1~2행 교체 권장]

> **스피커 노트**
> - 청중 직무 분포 확인 후 해당 행 위주로 설명
> - "사람의 몫" 열을 반드시 짚기 → 대체 불안 완화

## S12 · AI 취미 사례 ⏱ 1.5분

**핵심 메시지** — 업무 밖에서 먼저 손에 익음

# 3. AI 개념 / 하네스 (17분)

## S13 · 용어가 필요한 이유 ⏱ 1분

**핵심 메시지** — 용어 부재 → 요구사항 작성 불가

- 현상: "AI로 뭔가 해보자" → 무엇을 시킬지 미정 → 성과 없음
- 필요 최소치: 위임 대상·범위·금지선을 말로 정의할 수 있는 수준
- 목표: 오늘 이후 **요청서 한 장 작성 가능**

> **스피커 노트**
> - 용어 암기 아님을 명시 → 부담 제거

## S14 · AI 용어집 ① 기초 ⏱ 1.5분

| 용어 | 한 줄 정의 | 업무 비유 | 활용 포인트 |
|---|---|---|---|
| LLM | 문장을 예측·생성하는 모델 | 글 잘 쓰는 신입 | 만능 아님, 문서 업무에 강함 |
| 프롬프트 | AI에 주는 지시문 | 업무 지시 메일 | 구체적일수록 결과 안정 |
| 토큰 | 처리 단위 (글자 조각) | 작업량 단위 | 길이 = 비용 · 속도 |
| 컨텍스트 | 한 번에 참고 가능한 정보 범위 | 책상 위 자료 | 넘치면 앞부분 누락 |
| 할루시네이션 | 그럴듯한 오답 생성 | 확인 없이 단정하는 보고 | 사실 검증 필수 |

> **스피커 노트**
> - 5개 중 **할루시네이션**만 확실히 각인

## S15 · AI 용어집 ② 활용 ⏱ 1.5분

| 용어 | 한 줄 정의 | 업무 비유 | 활용 포인트 |
|---|---|---|---|
| RAG | 외부 문서를 찾아 근거로 답변 | 규정집 펴놓고 답변 | 사내 문서 기반 Q&A |
| 파인튜닝 | 모델 자체를 추가 학습 | 신입 재교육 | 비용 큼, 대부분 불필요 |
| 멀티모달 | 문서·이미지·음성 동시 처리 | 사진 보고 판단 | 도면·현장 사진 활용 |
| MCP · 커넥터 | 외부 시스템 연결 규격 | 사내 시스템 계정 부여 | 조회·등록 자동화의 전제 |

> **스피커 노트**
> - "파인튜닝부터 하자" 요구가 오면 → RAG 우선 검토로 유도

## S16 · AI 용어집 ③ 에이전트 ⏱ 1.5분

| 용어 | 한 줄 정의 | 업무 비유 | 활용 포인트 |
|---|---|---|---|
| 에이전트 | 목표를 받아 스스로 단계 수행 | 일을 맡길 수 있는 담당자 | 위임 단위로 사고 |
| **하네스** | 모델 주위를 감싸는 실행 구조 | 매뉴얼 · 계정 · 결재선 | 성과 차이의 실제 원인 |
| 툴(Tool) | AI가 호출 가능한 기능 | 결재 시스템 · 메일 | 없으면 조회·실행 불가 |
| 워크플로우 | 정해진 순서의 자동 처리 | 표준 작업 절차서 | 순서 고정 업무에 적합 |
| 가드레일 | 금지·확인 규칙 | 안전 수칙 · 승인선 | 사고 방지의 핵심 |

> **스피커 노트**
> - 하네스 = 오늘의 키워드 → 다음 2장에서 확장

---

## S17 · 핵심 개념 ① 챗봇 vs 에이전트 ⏱ 1.5분

**핵심 메시지** — "질문" vs "위임"

| 구분 | 챗봇 | 에이전트 |
|---|---|---|
| 입력 | 질문 | 목표 |
| 수행 | 답변 1회 | 계획 → 실행 → 검증 반복 |
| 외부 연결 | 없음 | 도구 통해 조회·실행 |
| 결과 | 참고 자료 | 완료된 업무 |
| 필요 조건 | 좋은 질문 | **하네스 설계** |

> **스피커 노트**
> - 대부분 조직이 챗봇 단계에 머무는 이유 = 하네스 부재

---

## S18 · 핵심 개념 ② 모델 vs 하네스 ⏱ 2.5분

**핵심 메시지** — 같은 모델, 다른 결과 → 차이는 하네스

- **모델 = 두뇌** — 판단·문장 생성 능력
- **하네스 = 손 · 눈 · 작업지시서 · 안전장치** — 능력을 실제 업무에 연결하는 구조
- 신입사원 비유

| 항목 | 사람 | AI |
|---|---|---|
| 역량 | 개인 능력 | 모델 |
| 업무 매뉴얼 | 표준 절차서 | 프롬프트 · 워크플로우 |
| 시스템 계정 | ERP · 메일 권한 | 툴 연결 |
| 참고 자료 | 규정집 · 과거 문서 | 컨텍스트 |
| 결재선 | 승인 절차 | 가드레일 |

- 결론: **역량 좋은 신입 + 매뉴얼·계정 없음 = 성과 없음**

> **스피커 노트**
> - 청중 대부분이 겪은 온보딩 경험으로 치환 → 이해도 급상승
> - "모델 바꾸면 해결" 오해 차단

## S19 · 핵심 개념 ③ 하네스 4요소 ⏱ 3분

**핵심 메시지** — 이 4칸이 곧 오늘의 워크시트

| 요소 | 정해야 할 질문 | 업무 예시 |
|---|---|---|
| **도구** | 무엇을 조작·조회 가능? | 메일 발송 · 사내 시스템 조회 · 엑셀 생성 |
| **컨텍스트** | 무엇을 미리 보여줄 것인가? | 규정 문서 · 과거 사례 · 표준 양식 |
| **루프** | 어디까지 스스로 반복? | 계획 → 실행 → 검증 → 재시도 |
| **가드레일** | 무엇을 금지·확인? | 대외 발송 전 승인 · 반출 금지 데이터 |

- 4칸 미정 → 에이전트 구축 불가
- 4칸 확정 → 구현은 IT·도구의 몫

> **스피커 노트**
> - 이 표를 워크시트와 나란히 제시 (항목명·순서 동일)
> - 청중 요청 = "구축해달라"가 아니라 **"이 4칸을 채워달라"**
